## Обязательный порядок включения

1. Дождаться окончания текущего этапа либо явной остановки пользователем;
   сохранить ID, checkpoint, commit и незавершённые изменения. Проверить
   отсутствие активной работы/harness/Hermes. Остановку не считать завершением разработки.
2. После перезапуска открыть только координатор, оставив рабочие задачи незагруженными.
   Проверить исходные SHA конфигурации и pinned runtime. Проверить фактические
   настройки hooks этой задачи. Подтвердить новые определения через штатный
   интерфейс Codex; не записывать выдуманный `trusted_hash`, не применять
   флаги обхода hook trust. Определения должны соответствовать подготовленным
   `hooks.json.pending` и текущему проверенному коду обёртки.
3. `flush_legacy_capture.mjs N`: дозаписать и завершить прежнюю партию capture штатным кодом OpenViking под
   прежним Peer. Успех проверить по состоянию и ответу сервера: не должно остаться
   неотправленного хвоста, активной блокировки или незавершённого `ovSessionId`.
   Один лишь код выхода hook этого не доказывает.
4. `install_task_config.py N` устанавливает подготовленный MCP override и
   `plugins."openviking-memory@openviking".enabled=false` только в данной рабочей
   папке. Это отключает исходные plugin hooks; глобальные настройки плагина
   не меняются. Поскольку bundled skills также исчезнут из каталога задачи,
   ссылки на официальные SKILL.md сохранены в AGENTS.md. Снова вызвать
   `review_hooks.mjs --trust`: для этой папки originalMemoryHooks должны быть пусты.
   Подтвердить завершение возможных async workers. Не отправлять задаче новый
   запрос до окончания следующего шага.
5. `migrate_task_state.mjs N --phase-boundary-verified` требует свежие receipts
   после установки и verified idle boundary. Он берёт официальный legacy lock,
   проверяет transcript tail, сохраняет внешний backup, переносит cursor с
   chmod 0600 и запускает SessionStart с `source:"resume"`. Флаг не заменяет
   проверку координатором. При сбое после переноса не восстанавливать старый backup.
   Helper сохраняет activation record после переноса; обёртка создаёт routing
   receipt только после проверки состояния официального hook. Две активные копии
   состояния и обнуление курсора запрещены.
6. Обновить подключение MCP этой задачи и проверить реальный `find/read` в actor
   scope. До этого старый процесс не считается обновлённым от изменения файлов.
   Не архивировать задачу и не удалять worktree ради перечитывания настроек.
7. Зафиксировать один реальный подтверждённый нюанс Loginom. Проверить фактический
   Peer нового capture, извлечение нужного знания в общий раздел, точное read-back
   и адресный поиск из другой задачи. Повторить первоначальный доступ для каждого
   потока; затем обращаться к памяти по потребности, без таймера.

## Существующая память и конкуренция

Старые worktree-записи не удаляются и не переписываются. Автоматическая смена
маршрута не переносит их. После переключения разработчик может сформулировать
подтверждённые прежние выводы в своей текущей задаче для общего capture; полные
старые журналы не переотправляются.

В исходниках сервера есть раздельные сессии, очереди по Peer и блокировки записи;
соответствие этих деталей живой версии не проверено этим набором локальных тестов.
Файловая блокировка не предотвращает смысловые противоречия. Новые знания должны
содержать версию Loginom, узел, условия, ветку/SHA и статус проверки. Незавершённая
ветка не меняет автоматически знания о принятом main или установленном плагине.

## Обратный переход

Остановить выдачу новых этапов и завершить текущий capture. Сверить, что нет
неотправленного хвоста. Вернуть исходные конфигурации только если их SHA совпадают
с планом и нет новых чужих изменений; включить штатные hooks и обычный MCP.
Перенести актуальный cursor, а не старую резервную копию. Не удалять полученные
знания и не переотправлять историю. Снова проверить фактическую маршрутизацию.
