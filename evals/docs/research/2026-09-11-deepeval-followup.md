# DeepEval: дополнение к сравнению, 2026-09-11

Статус: ограниченное read-only исследование после вопроса пользователя. В первоначальную четвёрку DeepEval не входил; утверждать, что он уже был рассмотрен и отвергнут, нельзя. Пакеты/skills не устанавливались, модели/eval не запускались, SUT не менялась.

## Вывод

**DeepEval технически подходит и заслуживает места среди готовых альтернатив.** Он не требует Python для нового TypeScript-контура, не требует Confident AI account для локального исполнения и допускает собственные программные проверки без LLM/API. Отклонять его как «Python-only», «только LLM judge» или «обязательный SaaS» было бы неверно. Сохранение Codex/Hermes CLI с существующей подпиской совместимо с архитектурой внешнего теста; готовая интеграция именно этого проекта ещё не проверена.

Основание пока предпочесть небольшой TS supervisor узкое: DeepEval не заменяет проектные функции изоляции, отдельного browser/Loginom storage, остановки попытки и независимой проверки сохранённого пакета. Однако его можно использовать **внутри того же решения** как библиотеку metrics, test-run results и локального просмотра, а не противопоставлять внешнему runner. Насколько это сокращает собственный report, надо определить коротким адаптерным spike на следующем этапе, не произвольным исключением кандидата.

Инженерная оценка сверх необходимой Loginom-специфичной работы: **0.5–1 день** для pinned TS-библиотеки, custom metric над verdict независимого verifier, интеграции Vitest и проверки локальных данных/семантики ошибок. Полный перенос существующих traces может добавить 0.5–1 день; в MVP он необязателен, canonical очищенные JSON traces остаются доступными независимо. Это оценка, не измерение. Confident AI web/self-host — отдельное решение и не требуется для первого цикла.

## Контракты и ограничения

| Вопрос | Подтверждённое | Вывод для Loginom |
| --- | --- | --- |
| Собственная deterministic metric в TS | `BaseMetric` публично экспортируется из `deepeval/metrics`; `measure(testCase, ...args): number \| Promise<number>`, поля `score`, `reason`, `success`, `error`, optional `model`, метод `isSuccessful()`. Контракт есть и в TS release 0.9.13 | Можно обернуть независимый verifier; LLM или judge API не обязательны. Это подтверждённая расширяемость, адаптер нашего verdict ещё не реализован |
| Готовые проверки без LLM | В TS source `ExactMatchMetric` сравнивает строки и не создаёт model | DeepEval не ограничен LLM judges. Но этот exact-match с `.trim()` не является нужным verifier схемы/Null/таблицы и не заменяет повторное выполнение Loginom |
| Внешний Codex/Hermes CLI | TS eval/Vitest принимает обычный async код пользовательского приложения | Test может запустить неизменённый авторизованный CLI или получить его сохранённый output. Это вывод из контракта, не проверенный end-to-end adapter; сам DeepEval не переносит подписку и не покупает API |
| Повторы | Python CLI имеет `--repeat`; в просмотренном TS `TestRunOptions` этого поля нет | Для TS объявлять независимые попытки через заранее сформированный список cases/run_id либо supervisor. Не переносить Python flag на TS без проверки |
| Семь исходов | TS `TestResult` содержит `success: boolean`; metrics имеют error/skipped/flaky и score | Наши PASS/FAIL/TIMEOUT/INFRA_ERROR/VERIFIER_ERROR/ABORTED/NOT_RUN надо хранить отдельным полем canonical result и явно отображать; threshold success не заменяет классификацию и знаменатели |
| Traces | Есть manual instrumentation, framework callbacks и OpenInference/OTel SpanProcessor; TS умеет оценивать завершённый собственный Trace | Нельзя утверждать, что ради любого eval надо менять SUT: black-box eval этого не требует. Для подробной Dock trajectory нужен отдельный converter существующих очищенных событий; готовый Dock/Hermes importer не найден |
| Локальный просмотр | `deepeval inspect` показывает сохранённые traces в терминальном UI; `deepeval view` ведёт на Confident AI | Локальная библиотека полезна и без SaaS. `inspect` — TUI, не готовый минимальный web dashboard |
| Confident AI | Web-платформа отдельна от локальной библиотеки; self-host подтверждён, требуется Enterprise license | Это организационная/инфраструктурная цена web-платформы, а не ограничение DeepEval library. SaaS-отправку без отдельного разрешения не включать |

## TaskCompletion и capture

[TaskCompletionMetric](https://deepeval.com/docs/metrics-task-completion) — LLM-as-a-judge по полному trace: задача и результат извлекаются/сопоставляются моделью. Метрики Step Efficiency, Plan Adherence и Plan Quality также относятся к trajectory-анализу. Это может быть дополнительной диагностикой, но не доказательством повторного открытия, выполнения и полного совпадения результата сохранённого `.lgp`. Само название TaskCompletion не даёт требуемого независимого verifier. В MVP эту метрику можно просто не применять; она не делает весь DeepEval непригодным.

[End-to-end docs](https://deepeval.com/docs/evaluation-end-to-end-llm-evals) различают black-box без tracing и trajectory/component eval с tracing. [Tracing docs](https://deepeval.com/docs/evaluation-llm-tracing) показывают instrumentation и integrations. В изученном коде есть преобразование OpenInference spans и оценка собственного Trace, но публичный turnkey импорт произвольных прошлых Dock traces в локальный viewer не подтверждён. Это остаточная неопределённость, а не заявление о невозможности. Нельзя подставлять приватное `_traceDict` как утверждённый стабильный внешний API.

[CLI docs](https://deepeval.com/docs/command-line-interface) описывают локальное сохранение и rolling latest snapshot. Независимые run manifests/results надо сохранять неизменяемыми под run_id; скрытые ожидания и traces прошлых попыток не передавать SUT. Существующие ограничения capture после `dock_prepare`, удаления чувствительного до persistence и запрета скрытых рассуждений/системных промптов сохраняются. SDK dependencies на OpenAI/OTel/PostHog не означают обязательные model calls; режим без лишних network/capture effects надо подтвердить будущим smoke-test, здесь его не было.

[Confident AI self-host FAQ](https://www.confident-ai.com/docs/self-hosting/faq) подтверждает Enterprise license и отдельную инфраструктуру; для proof-of-concept есть Docker Compose. Это не лицензия на open-source DeepEval. Langfuse при этом остаётся полноценным вариантом SDK experiments + local self-host observability; корректная формулировка общего решения — «не ставить платформу в критический путь первой недели», а не «Langfuse и DeepEval не подходят».
