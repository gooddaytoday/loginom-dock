# 11. Замена значений по внутренней таблице

Статус: **planned**. Новый подплан следующей аналитической волны.
Реализация и live-приёмка в рамках подготовки этого документа не выполнялись.
Навигация: [реестр](README.md), [общие требования новой волны](next-wave.md).
Зависимости: общая операция из [03](03-text-import.md), табличные mappings
и режим обычного Hermes из [09](09-hermes-user-diagnostics.md).

## Результат и границы

Один `node.apply` нормализует значения категорий или кодов через узел «Замена».
В первый scope входят внутренние таблицы точных замен для строковых, целых
и вещественных полей, без изменения типа; числовая точность явно равна нулю.
Для каждого выбранного поля задаются пары значений, регистрозависимость строк,
обработка остальных значений: сохранить, Null либо явное значение того же типа.
Поддержать замену исходного столбца и добавление производного с сохранением исходного.
Null, пустая строка и буквальный текст `null` различаются в типизированном запросе.
Внешние таблицы, регулярные выражения, ненулевая точность, преобразование типов,
дата/время, логические поля и «Замена (переменные)» остаются в roadmap.
Такие запросы не переводятся молча в частично похожий поддержанный режим.

## Что есть сейчас и источники

Компонент отмечен в `executor/inventory/palette-2026-09-05.json` как «Замена».
В `client/lib/node-contracts.mjs` этого типа ещё нет: требуется регистрация,
наблюдение мастера и handler, а не только добавление карточки компонента.
Общие привязки workflow/узла/портов, выполнение и чтение результата переиспользуются.

[Help «Замена»](https://help.loginom.ru/userguide/processors/transformation/substitution/)
описывает внутренние таблицы, выходные поля и добавление производного столбца.
[Точное совпадение](https://help.loginom.ru/userguide/processors/transformation/substitution/exact-match.html)
различает строковый Null и пустую строку; числовая точность влияет на совпадения.
[Остальные значения](https://help.loginom.ru/userguide/processors/transformation/substitution/other-match.html)
задаёт отдельную политику для отсутствующих в таблице значений. В примере
остальные→Null имеют флаг замены false: `_Replaced` не заменяет сравнение данных.
Пути от корней закреплённых источников Dock:

- Help: `data/processors/transformation/substitution/README.md`,
  `exact-match.md`, `other-match.md` в той же папке.
- E2E: `bg/sels/sReplace.ts`, `bg/sels/sMapping.ts`,
  `bg/helpers/wizards/variant_value_editor.ts`.
- E2E: `tests/toreview/helpers/al/replace_helpers.ts`,
  `tests/toreview/acceptance/wizards/replace/replace.ts`,
  `tests/toreview/acceptance/mapping/mapping_replace.ts`.

Источники и inventory не подтверждают работу handler на целевом Loginom.
Пути `toreview` — ориентиры для исследования; их успешный запуск не заявлен.

## Вход и выход операции

Вход: точный новый/существующий узел, один табличный источник с актуальной схемой,
полный набор правил для каждого изменяемого поля и явная политика выходных столбцов.
Поле определяется identity/именем в схеме, а не совпадающей меткой на экране.
На существующем узле заменять набор правил только перечисленных полей;
неперечисленные настройки и посторонние связи сохранять. На новом узле остальные
поля явно оставить без замен, проверив фактические значения по умолчанию мастера.
До жестов отклонять повторяющиеся ключи с учётом выбранного регистра, неверные типы,
неизвестные поля, коллизии выходных имён и режимы вне scope.
Если одинаковость строк зависит от ещё не проверенной локали Loginom, не угадывать её.

Выход общий: фазы, точные node/port refs, execution identity, схема и число строк,
ограниченная выборка, полнота и ссылка на evidence. Дополнительно читать созданные
поля `_Replaced` и, при добавлении, `_Replace`, сверяя реальные имена и типы.
Количество строк сохраняется; флаг не считать универсальным признаком изменения.
При «Готово» вернуть `execution=not_requested`, `output=not_refreshed`.
Сохранение черновика мастера не является сохранением пакета.

## Этапы реализации

1. Codex первым исследует реальный мастер в отдельной видимой сессии на целевом
   Linux-стенде: выбор поля, точная пара, typed Null, редактор и выходной mapping.
   Проверяет имена/типы служебных полей, флаги остальных значений и finish-переходы.
2. По Help, E2E и live-наблюдениям закрепить enum, границы и полное чтение правил;
   зарегистрировать тип и параметры в существующих контрактах и каталогах.
3. Внутри `node.apply` добавить/найти узел, подключить источник, настроить правила
   и порт. Проверять каждую применённую пару и полную итоговую таблицу до завершения.
4. Использовать общий finish/execute/result. Отдельный мастер выходного порта,
   если он нужен, пройти внутри операции; в обычном пути узел повторно не открывать.
5. Реализовать восстановление после потерянного ответа: сначала читать фактические
   правила и фазу, затем продолжать. Не создавать дубли строк, узлов или запусков.
6. После независимых локальных и live QA провести обычный запуск Hermes;
   порядок допуска и сбор доказательств заданы в [next-wave](next-wave.md).

## Проверки и приёмка

Независимые CSV и expected готовятся до сессии; сверяется весь небольшой выход.

- Несколько строковых категорий и числовых кодов: точные замены, сохранённые
  невыбранные поля и прежняя кратность строк; дробь не совпадает по округлению.
- Одинаковые тексты с разным регистром при обоих режимах и отказ для конфликтующих
  ключей; одинаковые метки у разных входных полей не смешиваются.
- Null, пустая строка и текст `null`: три разные пары, разные ожидаемые результаты.
- Остальные→сохранить/Null/значение: сравнить данные и штатные флаги отдельно.
- Замена/добавление выходного столбца: исходник, порядок, типы, новые поля и коллизии.
- Изменение существующего узла: старые правила выбранного поля заменены полностью;
  повтор operation ID, отказ до жеста, отмена и потеря ответа не удваивают действия.
- Пустой вход, широкая таблица правил, configure-only и сохранение пакета;
  отдельный Codex-аудит reopen/reexecute воспроизводит правила, схему и все строки.

Обычный Hermes получает только задачу и данные, завершает `package.save_checkpoint`;
использует существующую подписку `openai-codex / gpt-5.6-sol / low`.
Независимый auditor проверяет сохранённый пакет и свежий полный выход отдельно,
включая отрицательные подмены правила, режима, поля и чужого/старого результата.
PASS модели, отдельного unit-теста или одного флага для готовности недостаточно.
