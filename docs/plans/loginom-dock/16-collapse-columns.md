# 16. Свёртка столбцов

Статус: **planned**. Следующая аналитическая группа.
[Общий контракт и приёмка](next-wave.md), [реестр](README.md).
Зависимости: 01–03. Параметры полей 05 нужны только для сквозных задач с явным
преобразованием полученных значений в скалярный тип; сам узел сохраняет native-тип.

## Результат и границы

Преобразовать широкую таблицу, например «магазин, январь, февраль, март»,
в длинную: идентификатор магазина и отдельные строки показателей.
Поддержать один/несколько информационных столбцов, упорядоченный список
транспонируемых полей и оба значения флага «Игнорировать пустые значения».
Информационные поля сохраняют значения; формируются поля имён, меток,
значений и типов исходных данных.

Выходное поле значений имеет тип «Переменный», в том числе когда выбранные
столбцы выглядят однородными. Его нельзя объявить числовым по небольшой выборке
или превратить в строку для удобства чтения. Поддержать значения исходных
скалярных типов: целый, вещественный, строка, логический, дата/время, Null.
Входные поля уже переменного типа и управление через переменные — позднее.

## Исходная точка и источники

Компонент `component.transform.ColumnFlipping` есть в coverage, обработчика нет.
Чтение схемы уже распознаёт `variant` в `node-preview-schema.mjs` и
`node-table-context.mjs`. Это не доказывает передачу точного типа каждой ячейки
через `node-result-schema.mjs` и `user-v1`: проверка этого пути обязательна здесь.
В `table-output-values.mjs` переменная ячейка сейчас остаётся отображаемым текстом
с неподтверждённой точностью; `user-results.mjs` сокращает сведения о типе ячейки.
Включить эти модули в доработку: передавать подтверждённый исходный тип каждой
ячейки и её точность в `user-v1`. Одного `schema.type=variant` недостаточно для
различения числа `1` и строки `"1"`; тип нельзя угадывать по отображаемому тексту.

[Официальный Help](https://help.loginom.ru/userguide/processors/transformation/collapse-columns.html)
описывает две роли полей, четыре результирующих столбца и переменный тип.
Help: `data/processors/transformation/collapse-columns.md`.
Прочитан E2E `tests/acceptance/wizards/columnflipping.ts`: списки полей,
кнопки/перетаскивание, разные исходные типы, настройка игнорирования пустых значений.
Пиксельные смещения из теста не переносить в локальный handler без наблюдения
целевого UI; применять общие проверенные жесты.

## Контракт и локальная процедура

Вход — один источник; параметры явно разделяют информационные и транспонируемые
поля, определяют порядок, политику пустых значений и выходной mapping.
Не выбранные ни в одну роль поля исключаются только согласно полному запросу.
Одно поле не может одновременно иметь обе роли. Нужен минимум один
транспонируемый столбец; неизвестные или неоднозначные имена отклоняются до мутации.
При настройке существующего узла переданный набор ролей заменяется целиком;
выполнение без новых параметров сохраняет прежний набор.

1. Codex исследует живой мастер и результат на смешанных типах; проверяет смысл
   «пустого» для Null и пустой строки, фактические поля имён/меток/типов.
2. Проверить запрос, добавить/найти и связать узел, впервые открыть его мастер
   внутри общего цикла. Настроить роли и флаг с чтением полного списка.
3. Сопоставить результирующие поля с их семантикой, настроить имена, метки,
   исключения и порядок; не идентифицировать поле значения только по позиции.
4. Выполнить и прочитать таблицу. Сохранить native-значение и тип; отдельно
   вернуть ограничения чтения, если точность/тип не подтверждены. Если текущий
   reader их теряет, исправить общий путь и проверить прежние обработчики.
5. По каждой строке результата обеспечить проверяемую связь с исходным
   идентификатором, именем столбца и типом. Не полагаться на уникальность меток.
6. При частичном перемещении между списками проверить фактическое членство;
   повтор операции не добавляет поле второй раз. Общие finish/recovery/save
   сохраняют установленную семантику.

## Самостоятельные проверки

- При выключенном игнорировании пустых значений для N строк и K выбранных
  столбцов проверить N × K строк, кратности, информационные поля и значения.
- Включённое игнорирование: независимо посчитать строки по подтверждённой
  native-семантике; отдельно Null, пустая строка, ноль и false.
- Смешанные целое/вещественное/дата/строка/логическое значения; одинаковое
  отображение числа и строки не должно скрывать различие типов.
- Исключён выходной столбец «Типы данных»: краткий ответ всё равно сохраняет
  подтверждённый тип каждой ячейки значений, независимо от видимых метаданных.
- Два поля с одинаковой меткой, кириллица и переставленные входные колонки:
  исходное имя связывает значение с правильным показателем.
- Пустой вход, все выбранные значения Null, конфликт ролей, отсутствующее поле,
  широкая схема. Непрочитанный выход не выдаётся за ноль строк.
- Изменение набора полей и флага существующего узла, `done`/`close`, потеря ответа;
  после отдельного открытия пакета Codex проверяет настройки и новый полный выход.

Обычная задача Hermes: привести месячные столбцы выгрузки продаж к строкам,
сохранить магазин, название показателя и значение, сохранить пакет.
Codex проверяет весь результат и типы после повторного выполнения, включая
отрицательную подмену числового значения строкой с тем же отображением.
Готовность: оба режима пустых значений и смешанные скалярные источники приняты;
схема `variant` и точные данные проверены во внутреннем и пользовательском ответе.
