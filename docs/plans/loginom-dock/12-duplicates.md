# 12. Дубликаты и противоречия: разметка качества данных

Статус: **planned**. Новый подплан следующей аналитической волны.
Реализация и live-приёмка в рамках подготовки этого документа не выполнялись.
Навигация: [реестр](README.md), [общие требования новой волны](next-wave.md).
Зависимости: [03 — общий node.apply](03-text-import.md), работа с назначениями
входных полей и [09 — обычный Hermes](09-hermes-user-diagnostics.md).

## Результат и границы

Один `node.apply` настраивает и выполняет узел «Дубликаты и противоречия»:
выделяет повторяющиеся записи и конфликты значений по явно выбранным полям.
Scope — разметка исходных строк и чтение четырёх служебных полей.
Автоматическое удаление, выбор «первой»/«последней»/«лучшей» записи и разрешение
противоречий не входят в handler. Их требует отдельное решение аналитического сценария.
Нечёткое сравнение строк, интервальная близость чисел и нормализация ключей
остаются вне scope; при необходимости агент строит подготовку отдельными узлами.

## Что есть сейчас и источники

Компонент присутствует в `executor/inventory/palette-2026-09-05.json` под ID
`Дубликаты_и_противоречия`; в `client/lib/node-contracts.mjs` тип не зарегистрирован.
Нужны карточка, работа с назначениями входа, полный результат и независимый auditor.
Общие механизмы графа, мэппинга и выполнения уже есть; готовность нового типа
из существования общих механизмов не следует.

[Help обработчика](https://help.loginom.ru/userguide/processors/scrutiny/duplicates.html)
определяет дубликаты совпадением входных и выходных полей, противоречия —
совпадением входных при различии выходных. Хотя бы одно поле должно быть входным.
Выход содержит «Дубликат», «Группа дубликата», «Противоречие», «Группа противоречия»;
номера групп начинаются с 1. В примере отмечены все экземпляры повторяющихся записей.
Следовательно, фильтр `Дубликат=false` уберёт всю повторяющуюся группу,
а не сохранит одного её представителя. Это ограничение включить в карточку типа.
Пути от корней закреплённых источников Dock:

- Help: `data/processors/scrutiny/duplicates.md`.
- Help общих назначений и mapping: `data/workflow/ports/table-interface.md`,
  `data/workflow/ports/connections-interface.md`.
- E2E: `bg/selectors.ts` (`workflow.components.research.Duplicates`),
  `bg/helpers/workflow/ports.ts`, `bg/sels/sDataMapping.ts`, `bg/sels/sMapping.ts`.
- E2E: `bg/helpers/views/viewsForm.ts` содержит визуализатор Duplicates;
  это отдельная поверхность, не доказательство настройки обработчика.

В ходе подготовки не найден специализированный набор E2E самого обработчика.
Первый этап должен восполнить наблюдения; отсутствие набора не заменять догадками.

## Вход и выход операции

Вход: точный новый/существующий узел, один tabular output-port ref и его схема;
список ключевых полей с назначением «Входное», список сравниваемых — «Выходное».
Роль остальных столбцов задать явно после live-проверки доступных назначений:
они не участвуют в сравнении и должны сохраняться в результате.
Проверять непустой список входных полей, отсутствие пересечений/повторов,
существование каждого поля и полную текущую схему до изменения назначений.
Начальный scope допускает режим поиска дублей без сравниваемых выходных полей,
но его доступность и точная семантика требуют отдельной live-проверки первого этапа.
Если целевая версия его не допускает, явно сузить контракт до реализации.

Выход наследует фазы, refs, execution identity, схему, число строк и полноту чтения.
Читать служебные поля по подтверждённым именам и типам, сохранив исходные значения.
Число строк не уменьшается. Сравнивать состав групп по исходной identity строк;
не предполагать стабильную нумерацию между запусками без отдельного подтверждения.
Число отмеченных строк и число групп — разные показатели: считать по полному выходу
или возвращать недоступность полного подсчёта, если прочитан только sample.
Конфликт служебного имени с исходным не разрешать молчаливым переименованием.
Configure-only не запускает анализ и не возвращает прежнюю разметку как свежую.

## Этапы реализации

1. Codex первым проверяет реальный узел в отдельной видимой диагностической сессии:
   входные/выходные/неучаствующие роли, режим без выходных полей, реальный lifecycle,
   имена служебных столбцов, Null, пустую строку и отсутствие совпадений.
2. Зафиксировать поддержанную матрицу типов и ролей по UI, Help и общему E2E;
   неизвестную семантику сравнения обозначить ограничением до её проверки.
3. Зарегистрировать тип и handler: внутри `node.apply` добавить/найти, подключить,
   настроить назначения, завершить, выполнить и прочитать результат.
   Если отдельного мастера алгоритма нет, не вводить искусственный шаг его открытия.
4. Проверить весь эффективный mapping и отсутствие случайно активных ролей;
   при изменении существующего узла не оставлять прежние поля сравнения скрыто.
5. Добавить ожидаемые состояния, stale guards и восстановление по фактической фазе.
   После неизвестного эффекта не повторять назначения/выполнение вслепую.
6. Провести focused tests, Codex live QA, затем обычный Hermes и независимый аудит
   в порядке [общих требований](next-wave.md).

## Проверки и приёмка

До запуска приготовить небольшой набор с уникальным ID каждой исходной строки.
ID не участвует в сравнении; независимый expected описывает группы и флаги.

- Полные дубли: две и три копии отмечены все; исходная кратность и строки сохранены.
- Противоречие по одному из нескольких выходных полей: одинаковый составной ключ,
  разные значения; не объявлять конфликт дубликатом.
- В одной группе ключа есть и повтор, и другой результат: одновременно проверить
  оба флага и две системы групп, сравнив полный выход с expected.
- Совпадение только части составного ключа и уникальные записи: ложных групп нет;
  разный неучаствующий ID не препятствует обнаружению настоящих дублей.
- Null/пустая строка/текст `null`, строковые и числовые поля: ожидания закрепить
  на первом live-этапе; пустой вход не превращается в ошибку чтения данных.
- Отказ при нуле ключей, неизвестном поле и пересечении ролей; изменение ролей
  существующего узла, отмена, повтор operation ID и потеря ответа без дублирования.
- Configure-only; save и отдельный Codex reopen/reexecute: совпадают роли,
  исходные строки, флаги и состав групп, без обязательного совпадения номеров групп.

Обычный Hermes получает задачу и данные, использует существующую подписку
`openai-codex / gpt-5.6-sol / low` и финальный `package.save_checkpoint`.
Независимый auditor сверяет сохранённые роли и свежий полный выход;
отрицательные проверки подменяют ключ, роль, флаг, состав группы и identity запуска.
Удаление всех дублей не может засчитаться как успешная разметка или дедупликация.
