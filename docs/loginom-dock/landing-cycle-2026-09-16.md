# Один лендинг с последовательной сменой сцен — 16 сентября 2026

Пользователь выбрал объединение четырёх альтернатив: при каждой загрузке
страницы показывать следующую сцену по кругу с сохранением в LocalStorage.
Порядок фиксирован: clouds → glyphs → ribbons → voids → clouds.
Предыдущий workflow с объёмными узлами в этот цикл не входит.

## Реализация

- `landing/hero-selection.mjs` читает имя следующей сцены из единственного
  ключа `loginom-dock.hero.next-variant.v1`, проверяет его по списку и сохраняет
  следующую позицию. Пустое или некорректное значение начинает цикл заново.
- `hero-cycle.mjs` выбирает сцену один раз на документ. WeakMap отдельно
  защищает выбор и запуск одного root от повторов. Пауза/replay остаются
  внутри общего engine и не расходуют позицию очереди.
- Там, где доступен Web Locks, короткое чтение/запись сериализовано между
  вкладками. Блокировка освобождается перед динамическим импортом сцены.
- Выбранный постер и `data-variant` устанавливаются до lazy import; сбой
  загрузки/запуска оставляет соответствующий резервный кадр.
- `index.html` подключает общий entry и CSS четырёх сцен. Номерные подписи
  сравнительных вариантов не добавлены в основной интерфейс.
- `build.mjs` включает модули, CSS и постеры в будущую серверную сборку.
- `preview-variants.mjs cycle` запускает общий лендинг на 4173; без аргумента
  также запускаются фиксированные 4174–4177. Их entry не обращается к очереди.

Очередь относится к origin и профилю браузера, не передаётся на сервер.
Если LocalStorage запрещён, страница продолжает работать, но сохранение
следующей позиции недоступно. Без JavaScript показывается постер clouds.
Восстановление существующего документа из back-forward cache не считается
новой загрузкой. Случайный выбор, интервальное переключение и влияние
replay на очередь не используются.

## Проверки

- Новые тесты `client/test/landing-cycle.test.mjs`: 13/13. Проверены точный
  порядок и wraparound, storage между документами, неверные значения,
  read/write/getter denial, отсутствие изменений других ключей, единственный
  mount/выбор, lazy import, poster при ошибках, Web Locks и их fallback,
  настоящие pause/replay общего engine без сдвига очереди.
- Совместный прогон шести landing test-файлов прошёл; они включают 53 проверки
  цикла, установки, взаимодействия курсором, lifecycle, workflow и voids.
- В браузере на одном адресе 4173 подтверждены пять последовательных загрузок:
  clouds → glyphs → ribbons → voids → clouds. На каждом шаге выбранный постер
  загрузился, Canvas отрисовался, горизонтального переполнения нет.
- После паузы/replay остаётся clouds; новая вкладка этого origin получает
  glyphs, последующая перезагрузка основной вкладки — ribbons. Это проверено
  по фактически отрисованной сцене, без подмены браузерного хранилища.
- Все четыре фиксированных preview после перезапуска сохранили свои сцены,
  загрузились без ошибок страницы и не сдвинули очередь общего лендинга.
- Общая страница просмотрена при фактической ширине 1280 и 722 CSS px:
  узкая композиция работает, Canvas и постер соответствуют выбранному варианту,
  горизонтального переполнения и ошибок страницы нет. Resize не меняет сцену.

Проверки синтаксиса новых entry/selection и изменённых build/preview модулей,
а также `git diff --check` прошли.

Серверная сборка, публикация и клиентский выпуск не выполнялись. Предыдущая
граница клиентских test snapshots из отчёта landing-cursor сохраняется;
полная клиентская упаковка не входит в эту визуальную итерацию.
