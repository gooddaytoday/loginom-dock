# Windows: обнаружение npm Codex при установке Dock

7 сентября 2026 подготовлено исправление исходников по пользовательскому отчёту
об установке `0.1.0-rc.2`. Живая Windows-приёмка и новый выпуск ещё не выполнены.

В отчёте прямой `spawnSync('codex', ['--version'])` возвращал `ENOENT` в окружении
с npm `codex.cmd`, без отдельного `codex.exe`. Текущий код подтвердил такой способ
запуска и объединение ошибки запуска с отказом проверки версии. Версия
`codex-cli 0.153.2` принимается прежней функцией сравнения; минимум не менялся.
Первоначальная Windows-сессия в этой задаче не воспроизводилась.

`client/lib/agent-command.mjs` выбирает абсолютный путь по переданным PATH,
PATHEXT и cwd, сохраняя выбранную команду и окружение до конца установки.
EXE/COM запускаются напрямую, CMD — через `cross-spawn`; на POSIX сохраняется
прямой запуск. `cross-spawn@7.0.6` и `which@2.0.2` закреплены как прямые зависимости
в package.json/lock (обе версии уже присутствовали транзитивно).
Механизм подключён к preflight, snapshot, регистрации, удалению и восстановлению,
включая восстановление после ошибки. После отказа другой агент не выбирается.

Диагностика различает ошибку запуска ОС, ненулевой exit/signal и неподдерживаемую
или нераспознанную версию. Для выбранной команды показывается путь; ответ
нераспознанной версии ограничен 200 символами и JSON-экранирован.
Окружение и аргументы регистрационных команд в эти сообщения не включаются.
Проверка целостности комплекта сохранена. Новый модуль и тесты автоматически
попадают в существующий выбор `client/lib/` и `client/test/` упаковщика.

Проверено на macOS с Node.js 24.19.0:

- Целевые agent-command/native/diagnostics: 10 PASS, 1 Windows-only SKIP.
  Проверены выбор и сохранение агента, cwd/env, точная передача аргументов,
  отсутствие fallback, подключение native-операций и классификация ошибок.
- Полный клиентский набор: 371 PASS, 2 FAIL, 1 SKIP (374 tests). Два отказа
  относятся к `initial region discovery avoids a large document...` и
  `global toolbar is discoverable...`. Отдельный повтор обоих: 2 PASS.
  Причина зависимости результата от общего прогона не установлена.
- Проверки упаковки: 9 PASS, 1 FAIL. Не прошёл запуск полного клиентского набора
  из изолированного снимка: `native Table coverage survives actual pager and
  independent journal comparison`, дочерний процесс вернул status=null вместо 0.
  Этот UI-тест и его зависимости данным исправлением не менялись; причина
  отдельно не диагностирована. Это не успешная приёмка упаковки.
- `git diff --check` для изменённых клиентских файлов прошёл.

Windows `192.168.1.48:22` не ответил на SSH (ConnectTimeout=5). Запуск CMD,
сочетание npm/EXE, экранирование Windows, полная установка/переустановка/откат
пока не проверены на Windows. Для первого шага там запустить закреплённым Node
`node --test client/test/agent-command.test.mjs`; затем проверить настоящий npm
Codex и native-установку в отдельном профиле.

Перед передачей исправленного установщика пользователю нужны Windows-приёмка,
устранение или объяснение отказа изолированной проверки, штатная сборка на VPS
и проверка `verifyBundle()` нового комплекта. См. [releasing.md](releasing.md).
Публичный архив, сервер и метаданные лендинга этой задачей не менялись.

## Решение о выпуске

7 сентября пользователь явно разрешил выпустить исправление с пропуском
живой проверки Windows. Hotfix `0.1.0-rc.5` основан на опубликованном
`a00ea54642bda9f2f8bbbe1a60a2a1054656fd69` (`rc.2`) и содержит только исправление
запуска/диагностики, его зависимости и тесты, согласованные версии плагинов.
Незавершённые изменения основного checkout в hotfix не включены. Результаты
полного набора выше относятся к основному checkout, а не к этой ветке hotfix.
Сборки выполняются на VPS; проверка целостности и сверка опубликованных
контрольных сумм остаются обязательными.
